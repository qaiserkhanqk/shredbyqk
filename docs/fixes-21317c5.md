# Review and repairs of findings reported against 21317c5 (phone app `js/cycle/` and research prototype `research/`)

## Scope and method
- **Separation kept.** The research prototype and the phone app remain separate; nothing in the app calls the research engine.
- **Data and claims.** Synthetic data only. No clinical validation, ovulation confirmation, contraception suitability or launch readiness is claimed.
- **Reproduced first.** Every finding was reproduced on unchanged `21317c5`, first with probe scripts, then with regression tests written **before** any fix. The tests and their failing logs are committed in `498620d`:

| Suite (new) | Before the fix (on 21317c5) | After |
|---|---|---|
| `research/tests/regressions-21317c5.test.mjs` (Node) | **83 of 111 FAILED** | 111 of 111 pass |
| `research/tests/e2e-races.cjs` (Chromium) | **13 of 14 FAILED** | 14 of 14 pass |
| `tests/cycle-regressions-21317c5.test.mjs` (Node) | **7 of 9 FAILED** | 9 of 9 pass |
| `tests/cycle-ui-races.cjs` (Chromium) | **5 of 7 FAILED** | 7 of 7 pass |

The checks that passed before the fix are controls, guards, or valid cases the old code already handled. For example, month 13 and minute 60 were already rejected, and a one-night gap is still allowed.

**Test changes, stated openly:**
- **New browser tests tightened before committing.** Before the failing run was committed, three checks in the new browser test were made stricter, because they could pass for the wrong reason:
  - the mutation check now records the rendered participant before acting;
  - delayed responses are held at the response level, not the request level;
  - each preview scenario uses a fresh, never-imported file.
- **One earlier assertion updated to a new value.** In `research/tests/migration.test.mjs`, "schema version is 2" became "schema version is 3", because the schema version changed.
- **Nothing weakened.** No other existing test was changed, and no permission, consent safeguard or warning was relaxed.

| 1c | Legacy DB where optional consent was withdrawn before upgrading | After upgrade, quarantined `" lh_test "` / `" hormonal_medication "` rows remained | The older purge matched raw types exactly. **Fix:** schema-3 migration, in one transaction, after canonical-type backfill. The audit records counts only. Nothing is restored on later re-grant | `research/server/store.js` (`migrateToV3`) |
| 1d | Participant restrictions, consent at commit | Still enforced (guard checks pass) | Unchanged; covered by guards and the earlier suites | — |
| 2a | Dashboard preview binding | Changing the file or type left Commit enabled; a forced Commit imported the **old** preview; a preview from participant C was committed from B's page; a slow preview response enabled Commit for a newer file | One global `pendingPreview`. **Fix:** a preview is bound to participant, record type and file identity (name, size, modified time) and invalidated when any of them changes or on navigation. Stale preview responses are discarded. The commit sends `recordType` and `sourceHash`, and the server refuses a mismatch (409) without consuming the preview | `research/web/app.js`, `research/server/server.js`, `research/server/store.js` (`takePreview`) |
| 2b | Phone: inputs read late inside delayed or retried saves | A delayed save stored the date and values typed **afterwards**; a delayed "Period started" used the later date; two rapid saves both stored the second; a save waiting on another tab stored edited values | Handlers read the page **inside** the `repo.update` callback, which runs after the cross-tab lock and again on each retry. **Fix:** every handler snapshots its date, fields, checkboxes and data attributes synchronously when the person acts; the transaction uses only the snapshot | `js/cycle/ui.js` |
| 3a | Duplicate / conflict handling | A changed session ID, model, sampling interval, precision, manufacturer, time-zone name or sampling configuration was silently an **exact duplicate** | The content fingerprint omitted these fields. **Fix:** `observationRowHash` (`rowhash-2`) covers every analysis-relevant field, so a changed reading is quarantined as a conflict and the original kept. | 3b | Corrections with tied timestamps | A same-instant correction lost to its ancestor; a same-instant retraction did nothing | Supersession followed recorded-time order. **Fix:** supersession follows the correction **structure**: any known, well-formed correction supersedes its target regardless of time. Branches are resolved deterministically and reported (`conflicts`); cycles are dropped (`malformed`) | `research/lib/cycles.js` |
| 3c | Impossible timestamps | 30 Feb, 29 Feb 2026, 31 Apr and `24:00` were rolled into the next day; `+14:30` was accepted | `Date.parse` normalises. **Fix:** strict parser: every field is range-checked before conversion; leap years handled; offsets must be whole quarter hours within UTC−12:00…+14:00 | `research/lib/ingest.js` (`parseTimestamp`) |
| 3d | Vendor nightly values and the cutoff | A night labelled 2026-12-01 appeared in a 2026-11-15 analysis | Timestamp-free rows passed the time filter. **Fix:** documented convention (`config.night.vendorNightCompleteRule`): night D is complete at 12:00 local on D+1, at UTC−12 if no offset is given (D+2 00:00 UTC). Applied in the analysis; at import, a night not yet complete is quarantined. Historical nights import normally | `research/lib/config.js`, `ingest.js`, `pipeline.js` |
| 3e | Sampling intervals | 1e308 / 1e20 s accepted; the analysis **crashed** (`Invalid time value`); 86,400,000 s gave 1,440,000 minutes of coverage | No bounds; coverage used raw intervals. **Fix:** intervals must be finite and ≤ 3600 s (`limits.maxSamplingIntervalS`, justified in config), longer ones quarantined; one measurement may not exceed that either. A malformed group is reported as `processing_error` instead of crashing the analysis | `research/lib/ingest.js`, `quality.js`, `config.js` |
| 3f | Malformed CSV, JSON limits, prototype names | `"33".5` became `33.5`; a JSON record with 100 fields of 2000 characters was accepted; types `constructor` / `__proto__` crashed validation (server 500); `parseUnit('constructor')` returned a function | **CSV:** after a closing quote only a delimiter or line end may follow (`text_after_closing_quote`). **JSON:** same column and cell limits as CSV, nested values refused. **Lookups:** own-property only (`hasOwnProperty`) and a null-prototype unit map | `research/lib/csv.js`, `units.js`, `ingest.js` |
| 4a | Onset vs detection | For 33,33,33,33,34,34,34,34 the only possible onset reported was night 6, though night 5 was already high | The interval assumed the previous usable night was below threshold. **Fix (research):** separate `detectionNight`, `confirmationNight` and `possibleOnset` derived from observations: from the night after the last night at or below the baseline median, to the first observed elevated night. A rise during baseline formation, or no observations near the cycle start, abstains instead of "no clear shift". **Fix (phone):** a `possibleOnset` interval (spanning missing nights before the first high night), and an explicit statement that the rule cannot see a rise beginning while its baseline forms | `research/lib/inference.js`, `js/cycle/tempshift.js` |
| 4b | Long gap between baseline and confirmation | **Research:** 5 low nights, 55 missing days and 3 high nights were reported as a shift. **Phone:** did **not** reproduce; it already abstains (rule from 0f26696; guard test added) | **Fix (research):** configurable `maxJoinGapNights` (2, the same tolerance as inside the confirmation window) and `maxBaselineSpanNights` (12). | 4c | Value exclusion vs timing exclusion | One sample with a corrupted clock moved a whole session to another night (research and phone); excluding that sample did not fix it | Session labels used the earliest sample, including bad ones. **Fix (research):** "exclude" = the value is not used, but the timing is trusted. ## Assumptions that remain unvalidated
These are engineering choices, documented in config or code, **not** clinical thresholds:
- **Quality and import limits:**
  - maximum sampling interval 3600 s;
  - session-timing tolerance 18 h (research `night.sessionTimingToleranceHours`, phone `NIGHT_PARAMS.maxSessionSpanHours`);
  - vendor night completion at 12:00 local on D+1 (UTC−12 if no offset);
  - fallback window 21:00–09:00.
- **Shift rule:**
  - minDelta 0.25 °C (skin) and 0.20 °C (basal), MAD factor 2.5;
  - 6/5/3-night windows;
  - gap limits (maxJoinGapNights 2, maxBaselineSpanNights 12);
  - the minDelta step used to flag a rise during baseline formation.
- **Correction branches:** resolved by most recent leaf, then ingestion time, then entry ID.
- **Phone rule:** "three-over-six", DELTA 0.15, its span limits, and the choice of the longest session per night.

Synthetic tests show the code behaves as specified. **They do not show accuracy.** The changed evaluation numbers describe invented data only.

## Remaining steps before any real-world use
**1. Sample-band SDK testing (technical, not clinical).**
- **Obtain from the vendor:** the SDK or API, documentation and test data for the band.
- **Answer the integration questions:** the questions in `research/docs/supplier-checklist.md` / `research/lib/adapters.js`, covering timestamped samples or a derived nightly value, sampling, clocks, units, quality flags, IDs and firmware, de-duplication, backfill, cloud and licence terms.
- **Run the acceptance checks** on 3 or more people for 10 or more consecutive nights:
  - timestamps within 2 minutes of a reference clock;
  - off-wrist periods flagged;
  - firmware changes detected;
  - time-zone changes reflected in the offsets;
  - no duplicates on re-sync;
  - units confirmed on a bench.
- **Verify sleep-session classification:** check the vendor's sessions against a sleep diary and/or actigraphy.
- **Freeze** the firmware and configuration for any study.

**2. Independent prospective study (clinical, needs approvals).**
- **Approvals:** ethics approval, a DPIA, a legal basis for processing, consent materials and a registered protocol (draft in `research/docs/evaluation-plan.md`).
- **Population and references:** adult participants; independent references suited to each question:
  - urinary LH tests (an imperfect proxy);
  - transvaginal ultrasound in a sub-cohort;
  - prospectively logged period starts.
- **Analysis design:** pre-registered endpoints, participant-disjoint and temporal analysis, a locked test set, and reporting of abstention alongside conditional error with denominators. Subgroups by device, site and firmware.
- **Validate the assumptions:** every threshold listed above is checked on development data only, before the test set is unlocked.
- **No claims until then:** clinical use, ovulation confirmation and contraception claims all remain out of scope.
